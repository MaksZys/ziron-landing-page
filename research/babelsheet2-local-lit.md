# Babelsheet2 with a local Lit library/app

Research snapshot: 2026-08-02. Babelsheet2 source reviewed at commit [`bd59ccd`](https://github.com/TheSoftwareHouse/babelsheet2/tree/bd59ccd77ef2e80188d87b10af89170ae30095e9).

## Conclusions

- **It runs locally, but not independently of Google Cloud.** The CLI is a local Node executable (`npx babelsheet2 init`), but its supported workflow requires a Google service-account JSON credential, a Google Cloud project, and access to a Google Spreadsheet. The project README makes that prerequisite explicit; `init` validates service-account credentials and authorizes with Sheets and Drive scopes. ([README](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/README.md#L28-L56), [`auth.ts`](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/cli/src/lib/auth.ts#L11-L39), [`init.ts`](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/cli/src/command/init.ts#L231-L236))
- **No Google-hosted application server is needed.** Local development or CI can run the Node CLI and make outbound API calls directly to Google. However, without a Google project/service account and network access, `init` and translation fetching cannot use the supported spreadsheet source. This is an inference from the local CLI plus its mandatory authenticated API calls.
- **It is a developer/build-time fetch-and-generate tool, not a browser/runtime i18n library.** The CLI creates a project script that calls `fromBabelsheet`, groups entries by language, and writes JSON files to disk. The README says to run that script manually (or optionally in build/CI) and recommends checking the generated files before committing them. ([README](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/README.md#L85-L109), [generated script template](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/cli/src/script-template/flat-json-per-lang.ts.template#L1-L24), [JSON writer](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/json-writer/src/index.ts#L17-L45))

## Google APIs and permissions

| Purpose | API/method in the source | Required access |
|---|---|---|
| Create a new translation spreadsheet during `init` | **Google Sheets API v4**, `spreadsheets.create` | `https://www.googleapis.com/auth/spreadsheets` and/or Drive scope; Google documents the v4 create endpoint and scopes. ([source](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/cli/src/lib/babelsheet-generator.ts#L22-L62), [Google reference](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/create)) |
| Share the new spreadsheet with a translator/developer | **Google Drive API v3**, `permissions.create` | `https://www.googleapis.com/auth/drive`. ([source](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e9/packages/cli/src/lib/drive.ts#L17-L35), [Google reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions)) |
| Read the spreadsheet in the default path | Google Sheets API v4 through `google-spreadsheet` (`loadInfo`, `loadCells`) with a JWT scoped to Sheets | `https://www.googleapis.com/auth/spreadsheets`; the reader package declares `google-spreadsheet`, `googleapis`, and Drive dependencies. ([reader source](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/reader/src/spreadsheet-rows-iterator.ts#L19-L58), [wrapper source](https://github.com/theoephraim/node-google-spreadsheet#readme), [reader manifest](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/reader/package.json#L21-L28)) |
| Read via the experimental CSV path | **Google Drive API v3**, `files.export` with `mimeType: 'text/csv'` | `https://www.googleapis.com/auth/drive`; Google documents `files.export` as exporting Workspace documents to a requested MIME type. ([source](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/reader/src/csv-rows-iterator.ts#L12-L30), [Google reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/export)) |
| Remove the spreadsheet during `uninstall` | **Google Drive API v3**, `files.delete` | Drive scope. ([source](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/cli/src/lib/drive.ts#L38-L45)) |

The package manifests confirm that the CLI depends on `googleapis`, while the reader depends on `google-spreadsheet`, `googleapis`, and `@googleapis/drive`. ([CLI manifest](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/cli/package.json#L21-L28), [reader manifest](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/reader/package.json#L21-L28)) The implementation uses service-account JWT credentials, not browser OAuth; the credential file is explicitly required to be kept out of source control. ([README](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/README.md#L45-L56), [`auth.ts`](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/cli/src/lib/auth.ts#L11-L39))

## Fit with Lit localization

Lit’s official localization stack is `@lit/localize` plus `@lit/localize-tools`: author messages with `msg`, run `lit-localize extract`, edit XLIFF translations, and run `lit-localize build`. ([Lit localization overview](https://lit.dev/docs/localization/overview/), [Lit CLI/config](https://lit.dev/docs/localization/cli-and-config/)) Babelsheet2 does not depend on Lit and emits per-locale JSON objects keyed by dotted/nested translation paths, so it is **not a direct input format for `@lit/localize`**. ([Babelsheet2 reader output](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/reader/src/index.ts#L20-L25), [JSON writer](https://github.com/TheSoftwareHouse/babelsheet2/blob/bd59ccd77ef2e80188d87b10af89170ae30095e/packages/json-writer/src/index.ts#L17-L45))

Two viable integration choices:

1. **Babelsheet2 as the translation source of truth (lowest integration effort).** Run `npm run translations` before the Vite build, generate `src/locales/en.json`, `src/locales/pl.json`, etc., and import those static assets from the Lit app/library. Add a small locale store/message lookup layer that selects one generated object and causes components to update when the locale changes. Commit generated files if deployments must not contact Google. This keeps the service-account credential and Google network calls entirely in developer/CI tooling.
2. **Lit Localize as the rendering layer (richer template support).** Convert Babelsheet2’s generated entries into the XLIFF or generated locale-module shape expected by Lit Localize, or make Lit Localize the canonical translation workflow instead. Lit runtime mode generates one module per locale and supports `configureLocalization({loadLocale})`, dynamic locale loading, `msg(...)`, and automatic component re-rendering; transform mode instead produces a separate localized build with the localization runtime removed. ([Lit runtime mode](https://lit.dev/docs/localization/runtime-mode/), [Lit transform mode](https://lit.dev/docs/localization/transform-mode/))

For a local Lit/Vite app, the practical boundary is therefore: **Babelsheet2 fetches and materializes translations during development/CI; Lit/Vite ships and consumes the resulting local files.** Do not put the service-account JSON or direct Google API calls in browser code.
